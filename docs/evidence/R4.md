# R4 acceptance evidence

This document records the delivery checks that the authors executed. The accepted behaviour lives in [requirements](../requirements.md), [architecture](../architecture.md), and [deployment](../deployment.md). The repeatable procedures live in the [testing guide](../testing.md) and in the [installation guide](../installation-test.md). Each row names one procedure, the command that repeats it, and what it showed.

## Run environment

The authors ran every check on one machine. That machine ran macOS 15.8 on x86_64, with Eclipse Temurin JDK 21, Gradle 9.7.1, Node.js 24.21.0, Docker Engine 29.8.2, and Compose v5.5.1. The base image pins and their digests live in [dependencies](../dependencies.md).

## Executed procedures

| Procedure | Repeat with | What it showed |
| --- | --- | --- |
| Delivery stack lifecycle | `./gradlew containerSmoke` | The stack started healthy, and every container ran as an unprivileged user. Only the web service published a host port, and it served both the interface and `/api` from one origin. The board survived a stop and a start. The run removed its own containers and volume. |
| Health path of a running stack | `docker compose exec api curl -fsS http://127.0.0.1:8080/actuator/health/readiness` | Inside the API container the readiness path answered `200`. The same path requested from the host answered `200` with the web page, because the API publishes no host port. |
| Browser journeys on the production images | `./gradlew :frontend:frontendE2e` | Headless Chromium ran CRUD and colour editing, the `WIP_LIMIT_REACHED` refusal, a blocked note, guarded completion with a read-only `DONE` checklist, and a `409` conflict across two browser contexts. Each case ran against the production web image, the production API image, and MongoDB. |
| Backup and restore | `./gradlew backupRestoreVerify` | The dump produced an archive and a manifest. A restore into a new volume let a second stack report healthy and return the same snapshot, note, checklist, blocker, and revision. The procedure created the default restore target. A restore into an existing volume stopped without confirmation, and the teardown left no residue. |
| Documentation publication | `./gradlew documentation` | The bundle carries the Markdown guides, the OpenAPI document, and the generated API reference. The published index opened every guide and the generated reference. Every command named in the guides resolved to a declared Gradle task or to a repository script. |
| Release records, tamper rejection, and restart | `./gradlew releaseVerify` | `manifest.json` declared the version and the revision, and `compose.yaml` carried the same values as build arguments and image names. The script rejected a copy without `backend/build/libs/backend.jar`. It also rejected a copy whose records did not match `SHA256SUMS`. A stop without `--volumes` kept the board. |
| Clean installation, automated | `./gradlew cleanInstallVerify` | CI ran this task inside `fullVerify` on `main` at commit `4077af7`, and the job reported success. The task packages the bundle of the current revision. |
| Records of a published release | `./scripts/verify-release.sh sticky-notes-deliverables.zip` | The downloaded asset of release `v0.24.3` matched the digest that GitHub records for it. `shasum -a 256 -c SHA256SUMS` reported `OK` for 283 files. `manifest.json` recorded version `0.24.3` and revision `6a6533645832d58e89dc0d395ed199c2e6626927`, and `git rev-parse v0.24.3` printed the same commit. The JAR declared the same version and the same commit. |
| Clean installation of that published bundle | [installation guide](../installation-test.md) | Docker built `sticky-notes-backend:0.24.3` and `sticky-notes-web:0.24.3` from the binaries inside the ZIP. Only the web service published a host port, and it faced the loopback interface. An unknown API path returned JSON instead of the web page. The run created a note, and a restart kept the board. |

## Limits of this evidence

- The runs cover macOS 15.8 on x86_64 only. A recipient on another architecture or operating system must repeat them.
- The published records describe release `v0.24.3`. The head of `main` pins newer base images, so a recipient reads those pins through a later release.
- The restart test starts one bundle twice. It proves that a stop without `--volumes` keeps the board. It says nothing about a move of a running board to the image of the next release.
- The clean installation exercises the HTTP interface, not a browser. The browser suite exercises the test stack, not a downloaded bundle.
- The release records list every file in the staged bundle. The archive task excludes `**/.DS_Store`. A Finder artifact left in `build/release-bundle` produces a record that names a file the archive does not carry, so `./gradlew releaseVerify` rejects the bundle.
- These are local observations. They do not establish the status of the remote pipeline, of a review, or of a merge.
